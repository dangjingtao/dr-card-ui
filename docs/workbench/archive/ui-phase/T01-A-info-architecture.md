# T01-A｜完善信息流程设计确认

## 状态

PASS

T01-A 信息架构确认完成，进入 T01-B UI 实现。

## 页面定位

T01 不是普通个人资料页。

目标：

> 用户为了领取新人权益，完成必要信息补全。

设计优先级：

1. 新人权益领取体验
2. 信息采集完整性
3. 消费安全能力建设

## 已确认信息

字段范围：

- 昵称
- 生日
- 性别
- 身份
  - 学生
  - 教职工
- 消费密码

学生身份补充：

- 大一～大五
- 研一～研三

## 流程确认

采用分步 onboarding 流程：

```
权益引导
↓
基本信息
↓
身份补充
↓
安全设置
↓
领取成功
```

原因：

- 降低首次填写压力
- 强化新人权益感知
- 避免形成后台表单体验

## 消费密码定位

消费密码作为安全能力设置。

设计要求：

- 弱化视觉权重
- 不采用支付页面表达
- 不抢占新人权益主线

## 权益承接

完成信息后进入新人权益领取流程。

设计重点：

- 展示获得的权益
- 强化完成反馈
- 为会员、卡包、兑换等后续模块建立入口

## 历史设计参考规则

《不靠谱的设计历史》仅用于：

- 理解旧设计意图
- 查找已有业务语义
- 保留有效视觉资产

禁止：

- 直接复制历史页面
- 将历史交互作为当前定稿
