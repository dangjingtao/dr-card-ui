# T015｜全链路视觉、交互与回归验收

## 状态与类型

- 状态：`Accepted`（owner 于 2026-08-24 确认通过；60/60 节点、9/9 主链路、12/12 范围关闭及工程门槛均通过）
- 类型：Test / Review
- 优先级：P0

## 当前事实与差距

- 当前工程可类型检查和构建，但没有覆盖 60 个实施节点的页面巡检。
- 没有统一的原型对照截图、状态矩阵、交互目标、控制台检查和用户验收记录。
- 既往“自审 PASS”不能替代本卡。

## 目标

对 T005–T013 的 60 个实施节点进行全量视觉、交互、状态、路由和工程验收，并把失败项退回对应任务卡。

## 原型范围

- T005–T013 的全部 60 个实施节点。
- T014 的 12 个节点只验范围关闭，不验页面实现。

## 不在范围

- 不在验收卡临时补页面、改业务规则或掩盖差异。
- 不因构建通过自动将任何页面标记 Accepted。

## 依赖与阻塞决策

- 依赖 T001–T014 达到 `Agent Review` 或更高状态。
- 任一页面存在未决高风险设计时，本卡对应链路不得通过。

## 实施要求

- 生成 60 节点验收矩阵：路由/fixture、截图、视觉结论、状态结论、交互结论、工程结论、问题单。
- 375 × 812 为必测基准，并抽查窄屏、长文案和安全区。
- 主链路至少覆盖：新人领取、会员打卡/澡运、搭子邀请、商品兑换入包、卡券核销/转赠/兑换、地址订单、个人设置、消息、客服转人工。
- 检查所有交互的触发器、动作、目标和返回路径。
- 失败项关联回具体卡片，不以“已知问题”继续判过。

## 验收标准

- 60 个实施节点全部有结果，12 个关闭节点全部未偷渡。
- 无 placeholder、死链、假按钮、随机验收状态或阻塞性控制台错误。
- 关键页面有原型/实现并排证据及差异说明。
- `npm run typecheck`、`npm run build` 和生产预览 smoke test 通过。
- 智能体只能将本卡提交到 `User Review`；用户明确确认后才标记 `Accepted`。

## 必交证据

- 60 节点验收矩阵与截图索引。
- 9 条业务主链路操作记录。
- 工程命令输出、浏览器控制台与直达刷新结果。
- 未通过项及回退任务卡列表。
- 用户验收结论。

## 产出

- 验收报告、截图/录屏、问题单、最终用户验收记录。
