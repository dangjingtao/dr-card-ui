卡博士专项固定为 15 张主任务卡，索引见：

- [`design-assessment.md`](./design-assessment.md)：实际评估、覆盖与当前状态

## 2. 状态流转

```text
Draft → Ready → Doing → Agent Review → User Review → Accepted → Archive
          ↘ Blocked      ↘ Rejected ───────────────↗
```

状态含义：

- `Draft`：范围仍在整理，不能施工。
- `Ready`：依据、依赖和阻塞决策已齐，可以施工。
- `Doing`：正在实现。
- `Agent Review`：实现者已提交自检证据，但尚未进入用户验收。
- `User Review`：证据齐全，等待用户检查。
- `Accepted`：用户明确确认通过。智能体不得自行写入此状态。
- `Blocked`：存在明确产品、设计、接口或外部依赖阻塞。
- `Rejected`：自检或用户验收未通过，必须记录失败项并回到 Doing。
- `Archive`：已验收且相关结论已沉淀。

历史文档中的 `PASS` 只代表当时记录，不自动等于本任务系统的 `Accepted`。

## 4. 通过门槛

### 4.1 事实门槛

- 明确引用对应 Mockplus 节点和模块说明。
- 明确当前代码是完成、部分实现、占位还是缺失。
- 历史稿只能作为待确认参考，不能代替当前决策。

### 4.2 UI 门槛

- 375 × 812 基准截图与原型对照。
- 信息层级、布局、间距、主操作位置和品牌素材可解释。
- 空态、加载态、成功态、错误态、禁用态按卡片要求实现。

### 4.3 交互门槛

- 入口可达，返回路径成立。
- 点击、弹窗、Tab、表单、分享、核销等动作有实际状态变化或明确目标。
- 不能以静态高亮、假按钮或文字说明代替交互实现。

### 4.4 工程门槛

- `npm run typecheck`
- `npm run build`
- 页面直接访问与刷新不白屏。
- 控制台无阻塞性错误。

### 4.5 证据门槛

每张页面卡至少提交：

- 路由与覆盖节点清单；
- 原型依据截图或可定位页面信息；
- 375 × 812 实现截图；
- 状态/交互检查结果；
- 已知差异与未决项；
- 对应提交号。

## 5. 任务边界

- 主任务卡固定不超过 15 张；卡内可拆施工检查项，但不能借子项扩大范围。
- 页面实现卡、基础能力卡和最终验收卡分离。
- T014 专门管理暂缓/旧稿/试验页面，未经用户确认不得转入施工。
- T015 只做全局验收，不替其他任务补实现。
