## 1. 决策目的

T007 长期卡在三个阻塞项上：

- `B-004` 搭子（无/有）整页结构、搭子数量与默契值口径、底部按钮；
- `B-005` 邀请搭子二维码卡、用户胶囊、按钮与 IP 视觉可继承部分；
- `B-006` 搭子默契值「先不做」：严禁从 T14 历史稿反推需求。

任务卡「当前事实与差距」写明历史 T06/T07 对二维码卡片、用户胶囊、搭子数量和默契值做过大量二次设计，**不能直接沿用**；验收标准进一步要求「不出现 #31 默契值功能入口或历史 4 人 mock 数据偷渡」。这与 `AGENTS.md` §4.2 对 `不靠谱的设计历史/` 的定性一致：历史稿是证据材料，不是当前规范。

用户在本轮任务中给出两项口径：#30 用「WebView 边界页 + 弹窗两态」承载；分享失败态「只用 `?state=` 驱动」。

本记录据此关闭 `B-004` / `B-005` 的**可施工部分**，把仍缺原型依据的业务规则降级为 `BUDDY_RULE_STATUS` 夹具登记项，并把 `B-006` 落成一条**负向硬约束**（连同证据脚本的负向断言），使 9 个节点可在不倒推产品规则、不继承历史二次设计的前提下交付。

## 3. 决策细节

### 3.1 #30 边界页两态（D-055）

摹客 #30 全页只有一行「应用商店H5」文字与备注：未安装走应用商店 H5、已安装弹窗跳转 APP。据此：

- `?state=no-app`：`section[aria-label="应用商店 H5 承接边界"]` + 标题「应用商店H5」+ 显式边界标注「外部应用商店承接边界，不伪造商店页面」；
- `?state=has-app`：弹窗「打开 APP / 取消」，「取消」回落 `?state=no-app`（不是关闭页面——被邀请人此时仍在外部承接页），「打开 APP」接到 #36；
- 真实唤起（URL Scheme / Universal Link）与商店包信息属端能力与发布物料，本仓库不实现，登记在 `BUDDY_RULE_STATUS.inviteeLanding`。

证据脚本对此加了**负向断言**：页面内匹配 `/App Store|安装|下载卡博士/` 的元素数必须为 0，防止后续「顺手补全」把伪造商店视觉加回来。

### 3.2 失败态只由 URL 驱动（D-056、D-060）

适配层三个函数恒定返回成功分支，失败反馈文案只挂在 `?state=` 分支上渲染：

- `poster-failed` → 「保存失败 / 海报保存失败，请检查相册权限后重试」；
- `link-failed` → `role="alert"`「链接复制失败，请稍后重试」。

这与 T013 的 D-040（关键词确定性映射）**口径不同**，是用户在本轮的显式选择：T013 需要「用户输入 → 失败 → 重试成功」这条页内往返，而 T007 的失败源是端权限（相册 / 剪贴板），页内没有可映射的用户输入维度，硬造一个触发条件反而是自创规则。两者共同点是都禁随机、都可复现。

未接 `navigator.clipboard` 的另一原因：夹具环境受 https 与权限限制，真实调用会让成败随环境漂移，失去截图可复现性。

### 3.3 #28 多搭子档与默契值负向约束（D-058、D-059）

- `list` 档 1 个搭子、`multi` 档 4 个搭子，昵称全为原型的「小美」；`BUDDY_LIST_MULTI` 不写等级、不写默契值、不写互动次数；
- 功能介绍区固定 3 条，其中含原型文案「默契升级」——只保留字面文案，**不派生任何功能**；
- 证据脚本三条负向断言：`/默契值/` 文案数 = 0、历史 T07 默契值数值 `/\b(98|86|72|55)\b/` 数 = 0、非「小美」搭子行数 = 0。第三条防止「多搭子看起来更真实」这类审美驱动的人物编造。

### 3.4 重复邀请与跨路由闭环（D-061、D-062）

闭环③完整路径：搜索 `13900000000` → 「正在搜索…」→ 可邀请结果 → 发送邀请 → `?state=success&phone=13900000000` 成功弹窗 → 「我知道了」回 `/buddy` → 再点「手机号邀请」搜同号 → 「已经向该用户发送过邀请，请等待对方确认」且无「发送邀请」按钮。

`resolveBuddyPhoneOutcome` 先查会话内 `invitedPhones`，再落夹具映射，因此重复邀请是**真实状态推进**而非写死的 `?state=invited`（后者仅供直达截图）。

### 3.5 素材用途更正（D-066）

原 §2.6 登记把两张图写成横幅与二维码卡底图，而代码把它们用作圆形头像 —— 这是一处「登记与用法不一致」，必须查证而不是任选一边。查证结论是**清单错、代码对**：摹客原型内两图的全部图片节点都是 48×48 / 32×32 头像位。已同步做三件事：更正 §2.6 行与 §3 结论笔误、新增 §2.14 登记本卡落位素材（含 md5）、把 3 个素材补进 `scripts/extract-mockplus-assets.mjs`（复跑后 md5 与既有文件 `IDENTICAL`，脚本幂等）。
