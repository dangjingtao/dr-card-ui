## 3. 决策细节

### 3.1 Tab 与计数（D-010）

- 4 个 Tab 顺序：`全部` / `未读` / `系统` / `活动`。
- `全部` 的角标：有未读时显示未读数，无未读时显示消息总数（沿用 reference 表达）。
- `未读` 的角标：未读数；`系统` / `活动` 不带角标。
- Tab 是页面内本地态，不写入 URL；节点 #42（未读态副本）由 `?state=unread` 夹具进入并把初始 Tab 置为 `未读`。
- 列表按 `今天 / 昨天 / 更早` 三段分组，空组不渲染分组标题。

### 3.2 详情与已读（D-011、D-013）

- 详情正文、分类标签、时间、补充说明、CTA 全部来自 `:id` 命中的夹具项；命中失败渲染「消息不存在或已过期」空态并提供返回列表操作。
- 进入详情即调用 `markNotificationRead(id)`；返回列表后未读数、红点、Tab 角标同步变化。
- 已读集合是模块级 `Set` + 订阅广播，刷新页面即回到夹具初始状态，保证 `?state=` 夹具可复现。
- 标题栏取路由注册表的 `titleBarTitle`。因为壳层不支持页面级覆盖，该值必须是与分类无关的中性标题「消息详情」，不能写死「系统通知」，否则活动类消息会被误标。

### 3.3 一键已读语义（D-012）

- 入口在列表页正文右上角，未读为 0 时置灰并显示「全部已读」。
- 点击进入 `?overlay=clear` 确认弹窗：标题「确认全部标为已读？」，正文说明未读标记会被清除、消息本身仍保留在列表中。
- 确认后清空未读并弹出结果反馈 Toast「已全部标为已读」，1.6s 自动收起。
- 取消不改变任何状态。
