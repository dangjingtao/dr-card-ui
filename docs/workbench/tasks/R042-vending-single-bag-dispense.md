# R042｜自助售货机扫码购买：单包单选（T042 修复卡）

## 状态与类型

- 状态：`Agent Review`
- 类型：Fix / Change Request（R 系列修复卡）
- 优先级：P1
- 创建时间：2026-09-11
- 关联任务卡：T042（扫码购买 · 自助售货机）

## 背景

T042 已交付扫码购买页 `/vending/buy?id=xxx`：3 款洗发水体验包可独立加减数量，优惠券强制优先抵扣，支付后模拟出货。

2026-09-11 与硬件方核实结论：**自助售货机一次只能完成一包出货**，无法在单次支付中出多包。当前「每款独立数量加减」与硬件能力不符。

## 目标

- 移除每款洗发水旁的数量加减控件。
- 购买交互改为**单选一款洗发水出货**（每次支付固定 1 包）。
- 优惠券强制优先抵扣机制**保持不变**。
- 支付方式选择、确认支付、出货中/成功弹窗等其余链路**保持不变**。

## 不在范围

- 不改优惠券规则（仍为 1 张券强制抵 1 包 = 减 ¥1，不可取消）。
- 不改支付方式、支付中 loading、出货倒计时与成功弹窗结构。
- 不接真实后端/真实支付。
- 不扩展多 SKU、多包出货或购物流车。

## 硬件约束（事实源）

| 约束 | 说明 |
|---|---|
| 单次出货 | 一次支付最多出 1 包 |
| SKU 选择 | 用户在购买页选定具体哪一款洗发水 |
| 数量 | 不再暴露数量选择；隐式恒为 1 |

## 实施要求

### 购买页 `/vending/buy`

1. 商品卡片去掉 `+` / `-` 数量控件与数字展示。
2. 整卡可点击，改为**单选选中态**（radio 语义）：
   - 默认选中第 1 款（去屑洗发水）。
   - 选中卡片有边框/底色高亮 + 可见选中标识（如右上角对勾）。
   - 未选中卡片保持现有视觉，可点击切换。
3. 副标题改为体现「单包出货 / 任选一款」的文案（如「任选一款 · ¥1/包 · 体验装 10ml」）。
4. 底部结算：
   - 实付金额 = 所选商品价格 − 优惠券抵扣（仍强制）。
   - 有券时实付 ¥0.00，已优惠与件数文案同步为 1 件/1 包口径。
5. 出货成功弹窗商品摘要：显示所选款式名称 + 1 包（不再写「N 款共 N 包」）。
6. 无选中时确认支付禁用（单选默认已有选中，理论不可达，保留防御即可）。

### 优惠券区（不改逻辑）

- 可用张数徽标、强制抵扣、详情行金额展示逻辑维持 T042 原状。
- 有 1 张可用券时仍显示已抵扣 1 包。

### 其余

- 微信/支付宝单选卡片保持不变。
- 支付中 1.2s → 出货中 3s → 成功弹窗流程保持不变。
- 返回路径、演示入口入口保持不变。

## 状态与交互矩阵

| 场景 | 期望 |
|---|---|
| 默认进入 | 默认选中「去屑洗发水」，其余未选中 |
| 点击未选中商品 | 切换选中该款；价格/结算/优惠文案同步 |
| 再点另一款 | 单选互斥，仅一款选中 |
| 优惠券 | 强制抵扣 ¥1，实付 ¥0.00 |
| 无券场景 | 不在本期 mock 中改动（当前 mock 恒有 1 张） |
| 确认支付 | 可点击；支付中 → 出货中 → 出货成功 |
| 成功弹窗 | 展示所选商品名 + 1 包 + 实付 + 优惠 |
| 完成 | 返回首页 |

## 验收标准

1. `/vending/buy?id=vending-001` 上不再出现数量加减控件。
2. 三款洗发水仅一款处于选中态；点击可切换且互斥。
3. 优惠券仍强制优先抵扣；有券时实付 ¥0.00。
4. 支付方式、支付/出货/成功全流程行为与 T042 一致。
5. 成功弹窗商品信息为「所选 1 款 · 1 包」口径。
6. `npm run typecheck` 通过。
7. 智能体最多推进到 `User Review`，仅用户可标记 `Accepted`。
