# T034｜设备服务页

## 状态与类型

- 状态：`Draft`
- 类型：UI / Service / Device
- 优先级：P0

## 当前事实与差距

- 卡博士APP底部导航「服务」Tab 当前无实际页面，仅视觉展示（`LEGACY_TAB_ITEMS` 中 `service` 项无 `to`）。
- 首页四宫格快捷入口（淋浴 / 洗烘 / 饮水 / 吹风）当前纯展示，无点击交互。
- T030（设备扫码启动优化）已存在，覆盖扫码启动设备的功能优化，但设备服务列表页本身缺失。
- 「不靠谱的设计历史」中有设备服务相关参考稿，但不能直接作为当前规范，需用户确认。

## 目标

1. 建立卡博士APP的「服务」Tab 主页面，作为设备服务的统一入口。
2. 展示四类核心设备服务：淋浴、洗烘、饮水、吹风。
3. 打通首页快捷入口 → 服务页的导航链路。
4. 与 T030（设备扫码启动）衔接：服务页提供扫码启动入口。

## 原型范围

- 需求来源：首页四宫格快捷入口（淋浴/洗烘/饮水/吹风）+ 底部导航「服务」Tab + 「不靠谱的设计历史」参考（仅作参考，不直接照搬）。
- 页面区块：
  - 顶部标题栏：服务
  - 搜索栏（可选，用于搜索附近设备或服务）
  - 核心服务分类（淋浴 / 洗烘 / 饮水 / 吹风）
  - 扫码启动入口（与 T030 衔接）
  - 附近设备/推荐设备列表（待确认是否需要）
  - 我的设备 / 使用记录入口（待确认）

## 不在范围

- 不做真实设备数据对接（使用夹具数据）。
- 不做设备详情页（点击服务分类后跳转到哪里待确认）。
- 不做扫码启动的实际功能（由 T030 覆盖，本页仅提供入口）。
- 不做地理位置定位（附近设备为夹具数据）。

## 实施要求

- 服务页为一级 Tab 页，显示三项底部导航（首页 / 服务 / 我的）。
- 顶部标题栏显示「服务」，无返回按钮（一级 Tab）。
- 四类核心服务以卡片或宫格形式展示，每类有图标、名称、简介。
- 点击服务分类应有明确交互（跳转或展开），不能是假按钮。
- 页面整体风格与卡博士APP首页保持一致。
- 若有扫码启动入口，点击后跳 `/legacy-home/scan` 或 T030 指定的扫码页。
- 使用确定性夹具数据，不接真实后端。

## 状态与交互矩阵

- 服务页默认态（四类服务展示）。
- 点击淋浴 → 淋浴服务页或子功能列表（待确认）。
- 点击洗烘 → 洗烘服务页或子功能列表（待确认）。
- 点击饮水 → 饮水服务页或子功能列表（待确认）。
- 点击吹风 → 吹风服务页或子功能列表（待确认）。
- 点击扫码启动 → 扫码页（`/legacy-home/scan`）。
- 底部导航切换：首页 / 服务 / 我的。

## 验收标准

1. 服务页作为底部 Tab「服务」可正常访问。
2. 四类服务卡片布局、视觉还原正确。
3. 所有可交互入口有明确的点击目标。
4. 底部导航高亮正确（服务 Tab 高亮）。
5. 从首页快捷入口进入服务页路径正确。
6. `npm run typecheck` 和 `npm run build` 通过。
7. 页面直接访问与刷新不白屏。
