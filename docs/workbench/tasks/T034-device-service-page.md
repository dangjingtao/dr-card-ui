# T034｜卡博士服务中心（设备报修 / 意见反馈 / 热门问题）

## 状态与类型

- 状态：`Ready`

- 类型：UI / Service / Support

- 优先级：P0

## 当前事实与差距

- 卡博士APP底部导航「服务」Tab 当前无实际页面，仅视觉占位。

- 参考截图显示「服务中心」页面为客服/售后性质，而非设备分类列表：

  - 顶部"服务中心"标题，浅蓝色渐变背景

  - 客服机器人头像 + 欢迎语气泡

  - 两个大入口：设备报修（蓝色人形扳手图标）、意见反馈（橙色信封图标）

  - 热门问题列表 + 「换一换」按钮

  - 点击热门问题弹出底部弹窗，显示常见原因

- 设备保修流程：服务中心 → 设备报修项目 → 报修表单（设备编号/位置/故障现象/详情/电话/提交）

- 意见反馈流程：服务中心 → 意见反馈（文本框 + 提交）

## 目标

1. 建立卡博士APP的「服务」Tab 主页面 = 服务中心。
2. 完成设备报修完整链路：报修项目列表 → 报修表单 → 提交。
3. 完成意见反馈页面。
4. 完成热门问题列表 + 详情弹窗 + 换一换交互。

## 原型范围

**1. 服务中心首页（`/legacy-service`）**

- 顶部：「服务中心」标题，浅蓝色渐变背景

- 客服欢迎区：客服头像 + "Hi\~欢迎来到卡博士" 气泡

- 两大入口：设备报修、意见反馈（并排大图标 + 文字）

- 热门问题卡片：标题 + 换一换按钮 + 问题列表（3条）

- 底部三项导航（首页/服务/我的），服务高亮

**2. 热门问题详情弹窗**

- 底部弹出卡片样式

- 常见原因列表（多行文案）

- 底部"以上内容仅供参考"

- 点击背景/空白关闭

**3. 设备报修项目页（`/legacy-service/repair/projects`）**

- 紫色顶部栏：返回 + "设备报修项目"

- 账号信息：账号编号 + 总余额

- 项目卡片：项目名称 + 赠送金额 + 报修按钮

**4. 报修表单页（`/legacy-service/repair/form`）**

- 紫色顶部栏：返回 + "报修"

- 设备编号输入框 + 扫码图标 + 说明文字

- 设备所在位置输入框

- 选择设备故障现象（多选 checkbox，约12项）

- 详情说明文本框

- 报修人电话输入框

- 提交按钮（紫色渐变胶囊）

- 底部灰色区：维修员姓名 + 维修员电话（占位信息）

**5. 意见反馈页（`/legacy-service/feedback`）**

- 紫色顶部栏：返回 + "意见反馈"

- 大文本框："感谢您对我们的产品提出宝贵的建议和意见\~"

- 提交按钮（紫色渐变胶囊）

## 不在范围

- 不做真实报修提交（点击提交后显示成功 toast 即可）

- 不接真实设备项目数据（使用 fixture）

- 不做热门问题换一换的真实数据池（fixture 两批数据切换即可）

- 不做意见反馈提交后的后续流转

- 维修员姓名/电话为底部占位展示，不可编辑

## 实施要求

- 服务中心为一级 Tab 页，显示三项底部导航（首页/服务/我的）。

- 二级页（报修项目、报修表单、意见反馈）使用紫色渐变顶部栏 + 返回按钮，不显示底部导航。

- 整体视觉风格：卡博士紫色主题，圆角卡片，胶囊按钮。

- 热门问题弹窗：底部弹出，半透明遮罩，圆角卡片。

- 表单元素：灰色边框输入框，placeholder 浅灰，label 紫色文字。

- 所有页面宽度限制在 480px 内居中。

- 使用确定性 fixture 数据。

## 状态与交互矩阵

- 服务中心首页：默认态展示。

- 点击设备报修 → 报修项目列表页。

- 点击报修按钮 → 报修表单页。

- 填写表单 → 提交 → 成功反馈 → 返回报修项目。

- 点击意见反馈 → 意见反馈页。

- 填写反馈 → 提交 → 成功反馈 → 返回服务中心。

- 点击热门问题 → 弹出详情弹窗 → 点遮罩/关闭。

- 点击换一换 → 热门问题列表切换数据。

## 验收标准

1. 服务中心页作为底部 Tab「服务」可正常访问，底部导航高亮正确。
2. 设备报修链路：服务中心 → 报修项目 → 报修表单 → 提交成功，动线完整。
3. 意见反馈链路：服务中心 → 意见反馈 → 提交成功，动线完整。
4. 热门问题：列表展示正确，换一换可切换数据，点击弹出详情弹窗。
5. 所有二级页返回按钮正常工作。
6. `npm run typecheck` 和 `npm run build` 通过。
