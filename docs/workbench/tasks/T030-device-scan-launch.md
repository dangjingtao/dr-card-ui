# T030｜设备扫码启动优化

## 状态与类型

- 状态：`User Review`（首轮：淋浴/饮水扫码后直接启动，跳过金额选择；洗烘/吹风保持原流程）
- 类型：Feature / Flow
- 优先级：P2（会议补充）

## 当前事实与差距

- 会议讨论决定：淋浴、饮水、洗衣、吹风四大金刚设备统一改为扫码后直接启动，不再需要二次点击启动按钮。
- 扫码启动后出现结算按钮，与小程序保持一致。
- 相关需求在 `卡博士APP缺失及新增功能.xlsx` Sheet2 中多处提及：
  - #10 饮水和淋浴的启动按钮取消，扫码后直接启动。
  - #14 首页扫码按钮扫码后直接启动（淋浴和饮水直接启动，洗衣和吹风进入设备详情页）。
  - #20 扫码直接启动设备。
  - #1 蓝牙扫描设备功能（少数设备只支持蓝牙启动）。

## 目标

1. 淋浴、饮水设备：扫码后直接启动，出现结算按钮。
2. 洗衣、吹风设备：扫码后进入设备详情页，点击启动后开始。
3. 蓝牙扫码作为备选方案，当设备不支持二维码时启用。

## 原型范围

- 需求来源：`卡博士APP缺失及新增功能.xlsx` Sheet2 #10, #14, #20, #1 + 2026-08-31 会议笔记。

## 不在范围

- 不做设备详情页的完整重设计（仅调整扫码启动逻辑）。
- 不修改设备列表页结构（`常用`/`附近` Tab 已在 T023 讨论范围外）。

## 实施要求

- 扫码后根据设备类型分流：
  - 淋浴/饮水 → 直接启动 → 显示结算按钮。
  - 洗衣/吹风 → 进入设备详情页 → 手动点击启动。
- 扫码启动后页面展示设备运行状态和结算入口。
- 非扫码场景（设备列表页）的「启动」按钮行为保持一致。

## 状态与交互矩阵

- 扫码识别设备类型。
- 启动中状态。
- 启动成功（设备运行中 + 结算按钮）。
- 启动失败（错误提示弹窗）。
- 设备详情页（洗衣/吹风）启动流程。

## 验收标准

- 淋浴/饮水扫码后直接启动，无需二次操作。
- 洗衣/吹风扫码后进入设备详情页。
- 结算按钮在设备运行后正确展示。
- 错误场景有合理提示。

## 落地（2026-09-07 首轮）

- `DeviceDetailPage.tsx`：按设备类型分流启动逻辑。
  - 新增 `AUTO_START_TYPES = ['shower', 'water']`，淋浴 / 饮水进入页面后自动触发启动（`phase` 直接切到 `starting`），跳过"选择金额"区块和"确定启动"按钮。
  - 洗烘 / 吹风保持原流程：先选金额 → 手动点击启动。
  - 默认金额 5 元，结算 / 紧急停止 / 四步启动动画 / 余额扣减逻辑不变。
  - 设备列表页"使用"按钮入口与扫码入口共用同一详情页，行为自动对齐。
- `npm run typecheck` 通过。
