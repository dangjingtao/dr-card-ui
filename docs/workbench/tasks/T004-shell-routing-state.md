# T004｜应用骨架、路由与状态夹具

## 状态与类型

- 状态：`Accepted`（用户于 2026-08-21 明确确认通过）
- 类型：Infrastructure / UI
- 优先级：P0

## 当前事实与差距

- 现有 5 条路由，远低于 60 个实施节点所需的可达状态。
- 当前底部导航为“首页/卡包/兑换/我的”四项，尚未与原型主 Tab 和诗得丽专栏入口结构完成验收。
- 页面普遍没有可复现状态参数，截图验收会依赖随机或临时改代码。

## 目标

建立可支持 60 个节点的移动应用骨架、路由命名、导航关系和确定性状态夹具。

## 原型范围

- 全局主导航、二级页顶部栏、返回、弹层、APP 引导和直达路由。
- 业务节点可映射为独立路由或同一路由下的确定性状态，但必须可复现。

## 不在范围

- 不在本卡完成各业务页面视觉。
- 不把原型总览画布 #1 实现成业务首页。

## 依赖与阻塞决策

- 依赖 T001 节点矩阵。
- 必须确认主 Tab 数量、诗得丽专栏入口形态及 H5/APP 边界。

## 实施要求

- 输出路由表：路径、节点、入口、返回目标、状态参数、所属任务卡。
- 建立 deterministic fixture，禁止用随机数作为验收状态来源。
- 处理 safe area、滚动容器、底部导航遮挡、深链刷新和 404。
- 弹窗/底部弹层支持可复现打开状态，不用手工改源码截图。

## 状态与交互矩阵

- 主 Tab 切换与 active 状态。
- 二级页进入/返回。
- 弹窗打开/关闭/确认/取消。
- 深链直达与刷新。
- APP/H5 外部能力占位与回退。

## 验收标准

- 60 个实施节点全部能通过路由或 fixture 定位。
- 导航目标与返回路径无死链。
- 375 × 812 下无底部遮挡和安全区错误。
- 现有 5 路由不再承载错误语义或纯占位而被误判完成。
