# T025｜积分商城与泡泡值体系统一

## 状态与类型

- 状态：`User Review`（2026-09-07 完成签到页、积分明细页、pointsStore 与福袋入口施工，等待用户验收）
- 类型：Feature / Business Rule
- 优先级：P0（3-win）

## 当前事实与差距

- 现有积分商城入口未开放，旧积分数据未在 APP 展示。
- 会议讨论决定：旧积分失效，入口关闭，统一使用「泡泡值」体系。
- 命名规范明确：产业学院→「学历值」，卡博士→「泡泡值」。
- 虚拟物品与 SDL 产品做同一套 UI，品牌定位为「得力作为（专柜）」；仅放 SDL 和虚拟物品，进入上力供应链只是选择之一。
- 商城 V1 版只做 H5，但未来需要自己做原生。
- 积分商城入口（P0）在首页和积分页均有缺失。

## 目标

1. 积分商城入口开放，接入 H5 商城（WebView 边界页）。
2. 旧积分入口关闭，统一展示「泡泡值」。
3. 泡泡值资产体系落地：命名、展示、沉淀到页面 Token。
4. 虚拟物品 / SDL 产品统一 UI 设计。
5. 商城 V1 为 H5 承载，预留后续原生升级路径。

## 原型范围

- 需求来源：`卡博士APP缺失及新增功能.xlsx` Sheet1「积分商城」P0 + 2026-08-31 会议笔记。
- 复用现有 WebView 边界页（`/mall`）。

## 不在范围

- 不做旧积分迁移或展示。
- 不做原生商城（V1 仅 H5）。
- 不接入真实商品供应链。

## 实施要求

- 积分商城入口放到首页和泡泡值页的合适位置。
- 泡泡值命名统一为「泡泡值」（🫧），不得在 UI 中再出现「积分」表述。
- 虚拟物品 / SDL 产品 UI 复用同一套商城卡片组件。
- 商城 V1 以 H5 承载，使用 WebView 边界页（加载/成功/失败三态）。

## 状态与交互矩阵

- 积分商城入口默认态。
- H5 商城加载态 / 加载完成态 / 加载失败态（复用现有 WebView 边界页）。
- 泡泡值账户余额显示。

## 验收标准

- 积分商城入口可点击进入 H5 商城。
- APP 内无「积分」字样残留，统一为「泡泡值」。
- 虚拟物品与 SDL 产品在商城中使用统一 UI。
- 加载/失败态有正确的占位反馈。

## 实施与证据（2026-09-07 施工，状态 → User Review）

### 决策澄清

用户于 2026-09-07 明确以下方向，原卡目标范围扩展为「签到薅羊毛 + 积分明细 + 积分商城入口」：

1. **积分 = 泡泡值**：卡博士 APP 内叫「积分」，诗得丽品牌专栏内叫「泡泡值」，底层共用同一份余额和流水。
2. **积分商城共用**：H5 商城为同一外部链接，两端入口都跳 `/mall`（WebView 边界页）。
3. **广告 SDK 模拟**：preview 阶段用前端模拟广告（5 秒倒计时），真实 SDK 后续接入。
4. **每日打卡需看广告**：点击签到 → 弹广告 → 看完 → 签到成功 + 积分到账。
5. **视觉风格**：卡博士淡金色基调 + 红色主按钮（吸引用户点击），北极熊 IP 头图。
6. **为你精选**：3 个积分商城推荐商品 mock + 「查看全部」跳积分商城。
7. **广告位**：本期留空占位。
