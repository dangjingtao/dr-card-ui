# T039｜设置消费密码

## 状态与类型

- 状态：`Doing`

- 类型：Feature / UI

- 优先级：P2

## 当前事实与差距

- 学生在卡博士 APP 内**只需设置/修改自己的消费密码**，不参与"机器端输入尾号 + 密码"那种核销动作（2026-09-07 用户决定）。
- 当前的 `ConsumePinPage`（前版）是"机器端输入尾号 + 密码"流程，与用户的 APP 端诉求不符，需要改造为"设置消费密码"流程。
- 已有 `userInfoStore.pin` 字段（mock 默认 `000000`）。
- 「我的」页宫格已有的「消费密码」入口（KeyRound 图标，紧跟「收藏设备」之后）保留不变，指向新流程页 `/legacy-profile/machine-pin`。

## 目标

1. 把 `/legacy-profile/machine-pin` 改造为「设置消费密码」二步式流程。
2. 步骤 1：输入 6 位新密码（含协议勾选）；步骤 2：再次输入确认；提交写入 `userInfoStore.pin`。
3. 保留「我的」宫格的「消费密码」入口，复用 6 格方框 + 卡博士淡金色风格。

## 原型范围

- 顶部：金色渐变 + 「设置消费密码」标题。
- 步骤指示器：「① 输入密码 → ② 确认密码」（金渐变胶囊 + 灰色短线）。
- 当前状态卡：「当前消费密码：`00****`」首尾掩码（已设置）。
- 提示卡：根据步骤切换文案（浅金底）。
- 步骤 1：6 格方框输入新密码 + 协议勾选（整行居中）+ 金渐变「下一步」按钮。
- 步骤 2：6 格方框再次输入 + 金渐变「确认保存」按钮 + 灰色文字「返回上一步」。
- 错误反馈：
  - 步骤 1：非 6 位 / 未勾协议 → 红字。
  - 步骤 2：两次不一致 → 红字「两次输入的密码不一致，请重新输入」。
- 成功弹窗：金对勾 + 「设置成功」+ 「继续修改」/「返回我的」。
- 视觉与卡博士 APP 淡金色风格统一。

## 不在范围

- 不做忘记密码 / 旧密码校验流程。
- 不做修改与重置分离（直接覆盖 `userInfo.pin`）。
- 不做密码强度规则（mock 演示态足够）。

## 依赖与阻塞决策

## 实施要求

#### ConsumePinPage（改造，`/legacy-profile/machine-pin`）

- 顶部：金色渐变顶部栏 + 返回 + 「设置消费密码」标题。
- 步骤指示器：双胶囊 + 横线连接，金渐变高亮当前步骤。
- 当前状态卡：「当前消费密码」+ 首尾掩码展示（已设置）。
- 步骤 1：
  - 提示卡文案：「请输入 6 位数字作为新的消费密码，用于校园消费/核销时的身份验证」
  - 6 格方框 + sr-only 底层 input（复用 `PasswordVerify` 视觉）
  - 协议勾选（整行居中，金色径向渐变填充）
  - 「下一步」按钮：6 位填齐且勾协议后才可点
- 步骤 2：
  - 提示卡文案：「请再次输入刚才设置的密码以确认无误」
  - 6 格方框 + sr-only 底层 input
  - 「确认保存」按钮：6 位填齐后可点（loading 态禁用）
  - 「返回上一步」灰字链接
- 成功：mock 600ms → `userInfoActions.update({ pin: newPin })` → 弹成功弹窗。
- 失败反馈：步骤 2 一致性校验失败时红字 + 第 2 步方框保持可重输。

#### 路由 + 入口

- `/legacy-profile/machine-pin` 路由不变；「我的」宫格 `KeyRound` 入口不变（指向本流程）。
- routes.ts owner 更新为「设置消费密码页」。
