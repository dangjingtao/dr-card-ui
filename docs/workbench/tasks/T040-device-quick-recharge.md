# T040｜设备详情快速充值 + 设备列表扫码启动

## 状态与类型

- 状态：`Doing`

- 类型：Feature / UI

- 优先级：P1

## 当前事实与差距

- 设备列表页右侧按钮（`buttonText`）当前叫「启动 / 取水」，点击后 `navigate('/device/connecting?type=...&id=...')` 直接进设备详情。学生真实场景是「在机器旁扫码启动」，APP 内「启动」按钮的语义不准（用户 2026-09-07 要求回滚）。
- 设备详情页「账户余额」一栏只显示金额，没有「充值」入口。学生在机器上发现余额不足时，必须退出当前页面去 APP 充值再回来，链路长。
- T037 的「我的」+ 充值流程完整，但与设备详情场景割裂。
- T036 / T030 既有设备流程保持不变，只增加以下两条增量。

## 目标

1. 设备列表右侧按钮文案改为「扫码启动」（取水为「扫码取水」），点击弹本地扫码底部面板，模拟扫码完成后再进设备详情。
2. 设备详情页「账户余额」一栏右侧增加「充值」胶囊按钮（主题色），余额不足时按钮变红（描边）。
3. 点击「充值」弹本地快速充值弹窗（金额选择 + 充值成功反馈），不跳既有页面，留在设备详情。

## 原型范围

- 视觉源：现有设备主题色（`--device-400/500/600/100`），与项目卡片设计语言一致。
- 设备列表右侧按钮：金色（淋浴紫 / 洗烘绿 / 饮水蓝 / 吹风橙）胶囊。
- 设备列表扫码面板：底部 BottomSheet 风格，半透明黑遮罩 + 白色面板，含扫描框 + 模拟扫码完成按钮（与 T038 同款风格）。
- 设备详情余额栏：左侧「Wallet」+「账户余额」+金额，右侧新增「+ 充值」胶囊按钮（h-7 px-3 text-xs）。
- 快速充值弹窗：居中弹窗 + 金额选择（5/10/20/50）+ 微信支付（默认）+ 确认按钮 + 充值成功反馈。

## 不在范围

- 不改 T030「淋浴/饮水自动启动」逻辑，仅在余额栏加充值按钮。
- 不接入真实支付，仍走 mock 累加 `cardStore.balance`。
- 不新增独立快速充值路由（弹窗内闭环）。

## 实施要求

### 1. 设备列表按钮回滚「扫码启动」

- `app/fixtures/device.ts`：`DEVICE_THEMES[type].buttonText` 改为：
  - shower / laundry / hairdryer：`扫码启动`
  - water：`扫码取水`
- `pages/DeviceListPage.tsx`：点击卡片右侧按钮不再 `handleUse`，改为打开本地扫码面板（新增 `scanTarget` state 记录待启动的设备）。
- 新增 `ScanStartSheet` 组件（与既有 `BottomSheet` 同款，写在 `DeviceListPage.tsx` 内即可）：
  - 底部 BottomSheet：标题「扫码启动 {设备名}」+ 模拟扫描框（参考 `LegacyScan` 视觉简化版）+「模拟扫码完成」按钮（主题色渐变胶囊）。
  - 点击「模拟扫码完成」 → 关闭 sheet + `navigate('/device/connecting?type=...&id=...')`。
  - 点击遮罩关闭。
- 顶部固定扫码按钮（`scanButtonText`）保持不变，「扫码启动」是设备卡片右侧按钮的语义，与「顶部立即扫码」区分开。

### 2. 设备详情页余额栏加「充值」按钮

- `pages/DeviceDetailPage.tsx`：账户余额一行右侧改造：
  - 左侧：`Wallet` 图标 + 「账户余额」文字 + `¥{balance}` 金额（保留）。
  - 右侧：`+ 充值` 胶囊按钮（h-7 px-3 text-xs，主题色）。
  - **金额不足态**（`balance < selectedAmount`）：按钮变红色描边（`border border-danger text-danger`）+ 文案保持「+ 充值」。
  - **正常运行中**（2026-09-07 用户决定）：**移除禁用条件**，任何阶段（idle / starting / running）都允许点充值；扫码进入设备详情后，机器上发现余额不足也要能即时充值，避免还要先结束流程才能充值。

### 3. 快速充值弹窗

- `pages/DeviceDetailPage.tsx` 内新增 `QuickRechargeDialog`（与既有 `ConfirmVerify` 同款居中弹层）：
  - 标题「快速充值」+ 当前账户余额展示 + 4 档金额按钮（5/10/20/50）+ 「微信支付」选项（带勾选态，金渐变按钮）+ 确认按钮「确认充值 ¥{amount}」。
  - 提交：mock 600ms → `cardActions.set` 累加（先读现状，再 `map` 更新余额）→ 弹「充值成功」二级弹窗。
  - 「充值成功」二级弹窗：金色对勾 + 「充值成功」+ 「¥{amount} 已到账」+ 「继续使用」按钮（关闭弹窗，余额自动刷新）。
- 弹窗关闭：用户也可点「取消」/遮罩。

### 4. 工程门

- `npm run typecheck` + `npm run build` 通过。
- 视觉与设备主题色统一，不破坏既有暗色 / 浅色模式。
- 入口可达：设备列表 → 卡片右侧按钮 → 弹扫码面板 → 模拟完成 → 设备详情；余额不足时充值按钮变红可点。

## 状态与交互矩阵

- **设备列表**：默认态 / 卡片按钮点击 → 弹扫码面板 / 模拟完成 → 进入设备详情 / 顶部固定扫码按钮仍可用。
- **设备详情 余额栏**：余额充足（按钮主题色）/ 余额不足（按钮红色描边）/ 运行中（按钮置灰禁用）/ 充值弹窗（金额选择 / 支付方式 / 确认）。
- **充值弹窗**：默认态 / 金额选中态 / 支付方式选中态 / 加载中 / 充值成功二级弹窗 / 取消。
