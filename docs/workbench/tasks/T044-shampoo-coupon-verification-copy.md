# T044｜洗发水体验券核销方式说明文案调整

## 状态与类型

- 状态：`Ready → Agent Review → User Review`（智能体自检通过，请用户验收；按全局契约只有用户可以标 Accepted）
- 类型：Copy / Interaction Adjust（核销弹窗文案与控件）
- 优先级：P0（学生核心使用动线）
- 所属阶段：诗得丽品牌专栏施工（2026-09-09 批次）

## 当前事实与差距

- 现状（截图 1 红框区域）：弹窗内"选择核销方式"区块采用两个并列选项（扫码核销、消费密码核销），每个选项右侧带一个圆圈 radio，学生必须二选一。
- 问题：
  - 这本质上是"选择核销方式"，但学生视角下看到的应是"使用指引"，体验上像在考试。
  - 业务规则实际为：扫码核销时系统优先抵扣体验券；消费密码核销时由学生在设备上输入手机号 + 6 位消费密码并确认领取。这两条规则都需要明确告知。
- 需求：
  - 取消两个选项右侧的圆圈 radio。
  - 扫码核销行下方追加：「系统会优先抵扣体验券」。
  - 消费密码核销行下方说明文案调整为：「在设备上输入手机号和 6 位消费密码，点击确认即可领取，系统将优先抵扣体验券」。
  - 底部说明「同一张体验券仅可选择一种核销方式，确认后不可更改」可去掉或弱化（用户未提及，按需保留以解释不可改）。

## 目标

1. 把"选择核销方式"的并列互斥控件改成两段并列的指引说明。
2. 让文案明确告知学生"扫码会被优先抵扣"以及"消费密码核销需要在哪台机器上完成什么操作"。
3. 不改变最终核销结果（仍是扫码或消费密码两条路）。

## 原型范围

- 需求来源：2026-09-09 用户现场反馈 + 第一张截图。
- 节点：洗发水体验券弹窗 → 「选择核销方式」区块。

## 不在范围

- 不修改核销成功后真正的扫码/密码链路（T023 已 Accepted）。
- 不修改券的到期、限门店、库存等字段。
- 不修改券列表与券详情。

## 实施要求

- 「选择核销方式」区块调整为两行，每行结构：
  - 行 1：图标 + 标题（扫码核销 / 消费密码核销）。
  - 行 2：补充说明文字（灰色小字）。
- 移除每个 radio 圆圈，不再做"二选一"控件；不存在单选/互斥逻辑。
- 扫码核销：下方追加「系统会优先抵扣体验券」。
- 消费密码核销：下方替换为「在设备上输入手机号和 6 位消费密码，点击确认即可领取，系统将优先抵扣体验券」。
- 弹窗顶部 title 区域、副标题「请选择核销方式」需评估：用户提到点击按钮后看到的是"指引性内容"，因此建议把副标题改为「使用指引」或直接移除，避免学生被引导到选择控件的预期。

### 与原 PRD 的差异（已记录）

1. **副标题文案**：「请选择核销方式」→「**使用指引**」。PRD 原文为"评估是否改成『使用指引』或直接移除"，实施保留语义锚点（不用移除），改为「使用指引」。
2. **区块小标题「选择核销方式」**：PRD 未强制要求修改。实施选择**直接删除**该小标题，因两个 pill 已自带视觉主次（图标 + 标题），小标题属于冗余。
3. **顶部券卡的跳转按钮**：原为「查看商城体验券商品」按钮（点击跳 `/mall`）。实施选择**改为纯展示块**（去掉 onClick / ChevronRight / aria-label），学生一目了然确认是哪张券，不应误导点击跳走。该改动超出 T044 PRD 范围，但与"使用指引"语义一致（不要让弹窗里出现误导性控件）。
4. **底部 footnote 保留**：PRD 说"可去掉或弱化"。实施选择**保留并降级**（带 Info 图标的浅灰底块），避免学生误以为两条路可同时走。**B-045 决策落地**。
5. **Pill 样式强化**：两个核销 pill 在 PRD 之外被强化为：
   - 容器 `rounded-pill bg-surface-subtle p-3`，与券卡展示块视觉对齐
   - 图标方框 `h-10 w-10 rounded-full bg-surface text-reward-strong shadow-sm`
   - `flex h-20 w-full` 固定高度，两个 pill 等高
   - icon 和文字均 `self-center` 上下居中
   该改动未在 PRD 显式要求，但属于"使用指引"语义的视觉配套。
