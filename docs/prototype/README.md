# 卡博士 × 诗得丽｜摹客原型页面说明

> 本目录用于把现有摹客 RP 原型转换成可直接用于 UI 施工、页面验收和需求沟通的“原型语言”文档。
>
> 事实源：仓库中的摹客 RP 离线演示包（项目名「卡博士诗得丽」）及其 `data/project.js`、`data/pages/*.js` 页面数据。

## 1. 文档怎么读

这里不按接口、数据表或后端能力描述，而按原型本身表达：

- **页面定位**：这个页面在用户旅程里负责什么。
- **页面内容**：用户在当前页面能看到什么。
- **页面状态**：原型已经画出的默认态、成功态、空态、已领取态等。
- **主要交互**：点击什么，跳到哪里，或弹出什么。
- **原型备注**：摹客稿里已有的业务说明，原样保留其含义，不擅自补业务。

### ⚠️ 待确认历史设计标记

仓库根目录 `不靠谱的设计历史/` 中存在一批 T01–T14 历史 UI 稿。它们不是当前视觉规范，而是过去基于摹客、旧任务卡和当时判断做过的二次设计。部分页面甚至明确偏离了原始摹客结构。

因此，本目录将这些页面标为 **「⚠️ 待确认」**：

- 可以阅读历史稿了解过去尝试过什么；
- **不能把历史稿直接当成当前定稿施工**；
- 施工命中这些页面时，必须先与产品/设计负责人讨论确认；
- 只阻塞对应页面，不阻塞其他已经由摹客明确表达的页面。

## 2. 原型结构判断

原型项目为手机端，主要画板基准为 **375 × 812**。

摹客页面树中的「首页」不是单一业务页，而是一个**原型总览画布**：其中集中摆放了卡包、领取弹窗、今日澡运、地址、通知、搭子、客服、订单等大量业务画板。真正的业务页面又在页面树中分别存在。因此 UI 工程应按模块和真实页面拆分，不应把总览画布直接翻译成一个 React 页面。

## 4. 当前主链路

从原型交互看，诗得丽板块的主入口是「诗得丽专栏」。主链路可概括为：

1. 进入诗得丽专栏；
2. 未完善信息时，通过新人弹窗进入「完善信息」；
3. 日常首次进入时出现打卡提示；
4. 用户在会员中心查看泡泡值、打卡、今日澡运、卡包和洗头搭子；
5. 用户可进入洗护兑换专区，用泡泡值兑换样包并存入卡包；
6. 卡包中的券可核销、转赠，也可通过兑换码获取；
7. 「我的」承载订单、地址、客服、品牌福利官、卡包、资料设置等个人服务。

## 5. 原型中明确存在但本轮不擅自统一的差异

以下差异是原型事实，本目录只记录，不在文档阶段替产品做决定：

- 原型同时出现「泡泡值」与「积分」两套表达，并保留独立的「卡博士积分界面 / 积分明细」页面。
- 商品/品牌文案中同时出现「诗得丽」「DearSeed」「核心 DearSeed」等名称。
- 「卡券兑换」输入提示在不同状态里出现“8 位兑换码”和“11 位兑换码”两种文案。
- 原型区分 APP 与小程序能力：部分小程序缺失功能会弹出 APP 下载引导。
- 「健康管理」「数字空间」「搭子默契值」在页面名或备注中已经明确标记为“暂时不做 / 先不做”。
- 「颜色测试」属于设计试验页面，不视为业务页面。

后续 UI 开发如果要统一这些内容，应由产品/设计确认后再改，不从原型描述阶段反推业务规则。
