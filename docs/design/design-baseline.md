# 卡博士 APP UI 设计基线

## T001｜项目设计基线确认

## 项目定位

卡博士 UI 项目目标不是重新设计一个新产品，而是将 Mockplus 原型转化为可运行、高一致性的移动端高保真 UI。

设计策略：

> 原型业务结构保留 + Com Design 体系重构 + 卡博士品牌视觉升级

## 三方设计约束

### 1. Mockplus 原型（最高优先级）

作为产品意图与页面结构来源：

- 页面信息架构
- 用户流程
- 页面布局
- 业务对象
- 品牌资产

任何 UI 优化不得破坏已确认的产品逻辑。

### 2. Com Design（工程设计体系）

作为实现基础：

- Design Token
- 基础组件
- 移动端交互规范
- 组件复用方式

页面开发优先组合已有组件，而不是临时制作。

### 3. 《不靠谱的设计历史》（质量下限）

用途：质量约束，不作为设计素材库。

要求：

- 新页面质量不得低于该基准
- 不复制其中不足的视觉习惯
- 保持卡博士整体视觉连续性

## 品牌视觉方向

关键词：

> 年轻、活力、科技、可信

核心语义：

- Gold：会员、权益、高价值内容
- Orange：行动、转化、重要入口
- 其他辅助色服务信息表达

避免：

- 大面积黄金堆叠造成廉价感
- 游戏充值式视觉
- 普通电商促销风格

## 移动端原则

基准：375 × 812 pt。

关注：

- 单手操作
- 触控区域
- 信息层级
- 页面节奏
- 状态完整性

## 页面实现原则

页面优先级：

1. 核心流程页面
2. 业务组件沉淀
3. 扩展页面
4. 全量适配

验收标准：

- 符合 Mockplus 页面意图
- 使用 Com Design 体系
- 不低于视觉质量下限
- 可运行并通过构建
