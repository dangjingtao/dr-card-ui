# 体验包兑换动作接口建议（后续讨论草案）

> 状态：**Deferred / 非当前后端需求**
>
> 日期：2026-09-29
>
> 本文件原先把本轮需求理解成“兑换动作接口”，现已纠正。
>
> **当前需要与后端对齐的是体验装列表接口，不是兑换动作。** 请以 [experience-pack-list-api-proposal.md](./experience-pack-list-api-proposal.md) 为本轮事实源。
>
> 当前仅保留以下原则，供后续真正讨论兑换动作时参考：
>
> - 兑换应是一个服务端业务 action，而不是 H5 分别调用积分 CRUD 和卡包 CRUD 去拼流程；
> - 扣泡泡值与写入卡包应保持原子性；
> - 当前真实业务只有“通用体验包”，不应为了历史多商品 UI 先建设完整 SKU / 库存 / 订单 / 规则系统；
> - 具体路径、请求字段、错误码与事务实现均**尚未确认**，不在本轮给后端的要求内。
>
> 在后端确认兑换动作方案前，H5 的 H014 seam 仍只视为占位，不把任何未确认路径写成已实现接口。
