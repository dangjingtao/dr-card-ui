# 首页新人体验券页面级需求对照

> 更新时间：2026-09-22  
> 页面范围：正式 H5 首页 `/`（诗得丽品牌专栏首页）  
> 参考材料：用户提供的“请选择身份”弹窗截图；现有首页实现与新人体验券夹具  
> 当前阶段：页面级精修 + 原生 H5 联调；后端尚未开始

## 0. 已确认的混合项目 H5 架构前提

- 这是混合项目中的 H5 端，不把首页当成脱离宿主的独立网页。
- H5 页面初始化后，应立即通过已确认的 Native / JSBridge 能力向 APP 获取用户信息，以及可能存在的 token 凭证。
- 获取结果写入 H5 全局状态，后续页面和业务逻辑统一消费该状态；在下一次宿主信息更新前，继续使用当前全局状态。
- 首页新人体验券判断必须发生在这次初始化信息完成之后，不能先按默认身份弹出错误券数。
- APP 用户信息与 token 的具体字段、刷新/覆盖时机、失败和超时语义仍以 Native 联调契约为准；本文件不臆造字段名。

## 1. 结论先行

用户提供的“请选择身份”弹窗是**演示用弹窗**，不是正式产品流程。

首页正式逻辑不再让用户手动选择“存量用户 / 新增用户”，而是由宿主或后端提供用户分层结果，首页据此展示对应数量的体验券：

| 用户来源 / 状态 | 首页赠券结果 |
| --- | ---: |
| 从小程序进入的半新用户 | 1 张券 |
| 从未注册的用户 | 2 张券 |

## 2. 现状与目标对照

| 页面环节 | 当前实现（演示逻辑） | 目标实现（正式页面逻辑） | 处理结论 |
| --- | --- | --- | --- |
| 首页进入后的首个弹窗 | 展示“请选择身份”弹窗 | 不展示身份选择弹窗 | 移除正式首页路径中的 `IdentityPickerSheet` |
| 用户如何决定券数量 | 用户点击演示身份卡片 | 页面消费已解析的用户分层结果 | 不让用户手动选择业务身份 |
| “卡博士存量用户”分支 | 打开“新人礼包（占位）”弹窗，券种未定 | 不作为正式分支 | `NewcomerGiftSheet` 不进入首页正式链路 |
| “诗得丽新增用户”分支 | 固定展示 1 张洗发水体验券 | 对应“从小程序进入的半新用户”，展示 1 张券 | 保留 1 张券组合，但改为分层驱动 |
| 从未注册用户分支 | 当前演示弹窗没有对应正式分支 | 展示 2 张体验券 | 使用现有 `coupon-2` 组合承载页面态 |
| 领取成功 | 当前体验券弹窗已有领取成功反馈 | 保持现有成功反馈与“查看体验券”路径 | 本次只调整进入分支，不改视觉语言 |
| 关闭弹窗 | 关闭后停留首页 | 关闭后停留首页、不领取 | 保持现有行为 |

## 3. 页面级状态矩阵

| 状态 | 触发来源 | 页面表现 | 当前可否真实判定 |
| --- | --- | --- | --- |
| 半新用户 | H5 初始化后从全局用户状态读取“来自小程序且满足半新用户定义” | 首页新人体验券弹窗展示 1 张券 | 否，识别字段和契约尚未开始确认 |
| 从未注册用户 | H5 初始化后从全局用户状态读取“未注册” | 首页新人体验券弹窗展示 2 张券 | 否，注册状态来源和接口尚未开始 |
| 初始化中 | APP 用户信息尚未返回 | 页面等待分层结果，不先展示 1 张或 2 张券 | 需要 Native 联调确认 loading / timeout 表现 |
| 无法识别 / 未返回分层 | 宿主未提供有效分层结果 | 不得让用户选择身份；默认展示策略需由产品确认 | 当前未定，不在页面内臆造 |
| 关闭 | 用户点击关闭 | 弹窗消失，留在 `/` | 已有页面行为 |
| 确认领取 | 用户点击“确定” | 先展示领取成功，再进入体验券页面 | 页面链路已有，可继续复用 |

## 4. 本阶段 Mock / 验收边界

后端尚未开始，因此本阶段只验收页面根据不同分层结果呈现正确券数量，不宣称已完成真实识别或真实发券。

### 4.1 确定性页面态

继续使用首页已有的确定性状态作为视觉与交互验收入口：

| 入口 | 代表业务态 | 验收重点 |
| --- | --- | --- |
| `/?state=coupon-1&overlay=newcomer-coupon` | 半新用户，1 张券 | 券列表数量为 1，券内容和总数文案正确 |
| `/?state=coupon-2&overlay=newcomer-coupon` | 从未注册用户，2 张券 | 券列表数量为 2，券内容和总数文案正确 |

这些 URL 只是 preview/dev 的确定性 Mock 控制，不是线上参数，也不能替代 Native / 后端身份契约。

### 4.2 暂不定稿的接口问题

以下内容需在原生 H5 联调和后端开始后确认，当前文档不自行发明字段名或协议：

- Native 返回的用户信息是否已包含用户分层，还是 H5 需要携带凭证请求后端解析；
- H5 初始化调用的 capability 名称、返回 envelope 和 token 字段；
- 全局状态是仅内存保留，还是允许受控持久化；
- APP 重新注入信息、切换账号或 token 变化时的覆盖与清理规则；
- “来自小程序的半新用户”的判定字段、时间窗口和优先级；
- “从未注册”的判定来源及与登录态的关系；
- 1 张 / 2 张券的正式券种、库存、领取幂等和重复进入规则；
- 识别失败、未登录、接口超时和已领取用户的展示策略。

## 5. 页面施工要求

- 首页正式路径移除“请选择身份 / Demo 演示用”文案和身份选择卡片。
- 首页只保留一个新人体验券弹窗，根据分层结果切换 1 张或 2 张券内容。
- 首页初始化必须先完成 APP 用户信息 / token 的获取和全局状态写入，再决定是否展示新人体验券。
- 用户信息获取中、失败或超时时，不得静默套用错误用户分层；应按联调契约展示 loading、错误或待确认的降级态。
- 继续复用现有 `NewcomerCouponDialog` 的视觉与成功反馈，不新增第三套弹窗语言。
- 页面层不直接访问 `window` 宿主对象，不直接写临时 `fetch`；APP 用户信息应通过统一 bridge adapter / 全局状态入口注入。
- 在真实分层契约落地前，Mock 必须明确标识为验收态，不能写成真实用户识别结果。
