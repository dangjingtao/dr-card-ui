# Penpot 迁移工作方法

## 1. 文档目的

本文规定 `dr-card-ui` 从当前 React 高保真实现、Mockplus 原型和 Com Design 体系迁移到 Penpot 时的工作方法。

目标不是快速堆出若干单屏截图，而是形成：

- 完整可阅读的移动端长图；
- 不同状态独立、整齐、可检索的画板；
- 可复用的 Token、组件和品牌素材；
- 不依赖用户持续监工的 AI 验收流程；
- 可以由低成本模型承担前期机械工作的受控流水线。

## 2. 事实源优先级

发生冲突时，按以下顺序执行：

1. 用户在当前任务中的明确确认；
2. 当前代码 UI 的实际渲染、状态、交互、Token、组件和真实素材；
3. 当前代码中的 fixtures、router 与已验收任务记录；
4. 当前已确认的 Mockplus 原型和 [`../prototype/`](../prototype/README.md) 文档；
5. [`../design/design-baseline.md`](../design/design-baseline.md) 与其他已确认设计文档；
6. `不靠谱的设计历史/` 中的历史参考；
7. 智能体推断。

第 6、7 项不能替代前面的事实源。遇到原型缺口、历史冲突或产品规则未定时，页面进入 `BLOCKED`，不得自行补齐。

本迁移的交付对象是当前代码 UI。Mockplus 与文档用于追溯和差异登记；当它们与代码 UI 不一致时，不得把旧原型重新画回 Penpot。

## 3. 交付契约

### 3.1 长图

- 可滚动页面必须交付完整长图，不能只保留 375 × 812 首屏。
- 画板宽度以 375 为移动端基准。
- 画板高度来自已确认页面的完整渲染高度或明确测量，不得默认猜成 812。
- 固定底栏、悬浮按钮和弹层需要按实际状态单独表达，不能依靠画板裁切掩盖内容。

### 3.2 状态独立

- 默认、加载、空态、错误、禁用、成功、选中、弹层等有意义状态必须独立成图。
- 不同状态不能隐藏在同一个画板中，也不能互相覆盖。
- 同一路由的状态画板相邻排列，并保持相同宽度、内容基线和命名顺序。
- Debug 面板和工程夹具不得混入默认产品画板；确有验收价值时，单独放在工程状态区。

### 3.3 复用

- 共享按钮、导航、卡片、标签、表单、弹层等必须使用真实组件实例。
- Token 必须保持实际绑定；颜色值相同但没有绑定，不算复用。
- 品牌/IP、会员卡、人物、活动 Hero 等必须使用仓库真实素材，不得用色块或近似图代替。
- 缺少字体、素材、Token 或组件时停止写入并报告，不得临时替换。

## 4. Penpot 画布组织

建议的页面层级：

```text
00 / Foundations
01 / Components
10+ / Business Modules
90 / Review
```

业务画板命名：

```text
序号 / 模块 / 路由 / 状态 / 375xLong
```

示例：

```text
01 / Member / membership / Default / 375xLong
02 / Member / membership / Claim Success / 375xLong
03 / Member / membership / Empty / 375xLong
```

排布规则：

- 同一路由状态从左到右排列；
- 不同路由分组排列，不交叉穿插；
- 业务画板以 `(120, 120)` 为首个基准点；同一行水平 gap 固定为 80px，按 `nextX = currentX + currentWidth + 80` 计算；
- 同一状态组必须共用相同 `y` 基线，禁止凭目测拖放形成 25px、80px、125px 等混合间距；
- 需要换行时，下一行 `y = 上一行最高画板底部 + 160px`，同一行从 `x = 120` 重新开始；
- 画板名、状态名和顺序保持一致；
- 批注放在画板外，不进入产品界面；
- 被拒绝的实验稿不得与正式画板混排。

## 5. 使用的技能

### `penpot-migration-dispatch`

用途：派发低成本只读任务、生成页面 Manifest、控制批次、执行写入门禁并汇总结论。

位置：`$CODEX_HOME/skills/penpot-migration-dispatch/SKILL.md`

配套资源：

- Manifest 规范：`$CODEX_HOME/skills/penpot-migration-dispatch/references/task-card-and-manifest.md`
- Manifest 校验器：`$CODEX_HOME/skills/penpot-migration-dispatch/scripts/validate_manifest.py`

### `penpot-ui-polish`

用途：仅在受控 Penpot 写入、结构审计或视觉验收时使用。负责 Token/组件链接、画板组织、导出检查和 P0–P3 质量判定。

位置：`$CODEX_HOME/skills/penpot-ui-polish/SKILL.md`

低成本侦察卡和 Manifest 卡不得使用该技能写入 Penpot。

### `skill-creator`

用途：只有当迁移方法已经由真实批次验证，且需要固化或修订技能时使用。不能先把未经验证的流程包装成规范。

位置：`$CODEX_HOME/skills/.system/skill-creator/SKILL.md`

## 6. 角色和权限

| 角色 | 建议模型 | 允许内容 | 禁止内容 |
| --- | --- | --- | --- |
| 调度者 | 主模型 | 定范围、发卡、判断冲突、验收、汇总 | 把判断责任下放给低成本模型 |
| 侦察卡 | 低成本模型 | 只读盘点页面、素材、状态、Token、组件 | 打开或修改 Penpot |
| Manifest 卡 | 低成本模型 | 为单一路由生成结构化施工清单 | 自行设计、猜尺寸、补规则 |
| Penpot 写入者 | 单一受控写入者 | 按已验证 Manifest 写一个页面或状态组 | 同文件并发写、扩建设计系统、替换素材 |
| 验收者 | 主模型 | 做结构检查和有限视觉检查 | 仅凭写入者自报结果通过 |

同一个 Penpot 文件同一时间只能有一个写入者。

## 7. 批次流程

```text
用户需求
  ↓
页面分类：direct / confirm / exclude
  ↓
低成本模型生成单页 Manifest
  ↓
Manifest 校验与写入门禁
  ↓
单一写入者创建长图和独立状态画板
  ↓
AI 结构检查 + 有限视觉导出
  ↓
WRITTEN / BLOCKED / REJECTED
  ↓
用户阶段性抽查
```

默认批次最多包含三张并行只读卡；Penpot 写入始终串行。

### 7.1 施工底包与页面差量

所有迁移卡必须引用 [`penpot-construction-base.md`](./penpot-construction-base.md)。该文件持久记录已经完成的 Token、组件、素材治理、Penpot 当前库存和用户决策。

低成本模型不再执行全量盘点。每张卡只处理当前路由相对底包的差量：页面区块、状态、文案、真实素材、交互和长图实测高度。底包未列出的 Penpot 原语必须标记为 `MISSING_PRIMITIVE`，统一进入基础设施批次，不得在页面卡中猜名。

同一批卡片不得重复读取相同的全局文档或重新枚举 Penpot 库。调度者应把所需底包片段直接放入任务上下文，避免低成本模型为恢复背景消耗 Token。

独立工作树可能落后于当前工作区。派卡前必须确认它包含任务所依赖的 Accepted 版本；否则直接注入当前页面事实和必要源片段，并禁止任务从旧分支自行补全。读取到与底包冲突的旧实现时，卡片直接 `REJECTED`，不能进入写入门禁。

## 8. Manifest 门禁

每个页面 Manifest 至少包含：

- 路由和任务编号；
- 事实源路径及其角色；
- Penpot 文件、页面和画板命名；
- 完整长图的高度来源；
- 独立状态画板列表；
- 按顺序排列的内容区块；
- 真实素材路径；
- 代码组件到 Penpot 组件的映射；
- 代码 Token 到 Penpot Token 的映射；
- 文案、交互和目标页面；
- 停卡条件；
- 结构和视觉验收要求。

JSON Manifest 使用以下命令校验：

```bash
python3 "$CODEX_HOME/skills/penpot-migration-dispatch/scripts/validate_manifest.py" path/to/manifest.json
```

未通过校验的 Manifest 不得进入 Penpot 写入。

## 9. 写入门禁

开始写入前必须确认：

1. 页面属于 `direct`，或相关决策已由用户明确确认；
2. `penpot.currentFile.id` 与目标文件 ID 完全一致；
3. 页面、画板、状态和排布名称明确；
4. 所有必需字体和素材存在；
5. 使用的组件和 Token 已列入 Manifest；
6. 长图高度有事实依据；
7. 没有另一名写入者同时操作目标文件。

写入时不得顺手修改全局 Token、共享组件或其他页面。

## 10. AI 验收门禁

AI 应承担常规验收，用户只做阶段性抽查。

### 结构检查

- 文件、页面和画板名称正确；
- 长图尺寸和状态数量正确；
- 画板排布整齐、无标签碰撞；
- 必需区块、素材和文案齐全；
- 无未批准占位图、替代字体和施工说明；
- 无非预期越界、裁切、重叠或不可读文字；
- 共享组件保持实例链接；
- 关键属性保持 Token 绑定；
- 交互具有真实目标和动作。

### 视觉检查

- 检查完整长图；
- 对密集文字、图标、素材裁切和关键操作区做局部检查；
- P0、P1、P2 问题必须清零后才能进入 `WRITTEN`；
- 导出超时不自动重试，记录后停止。

### 状态定义

- `READY`：Manifest 完整，可以写入；
- `WRITTEN`：已写入并通过结构与视觉验收；
- `BLOCKED`：需要明确的产品或设计决策；
- `REJECTED`：结果存在，但不值得继续修复或不能作为模板。

只有用户可以把阶段成果视为最终设计确认。

## 11. 成本控制

- 页面、路由、素材和组件总盘点只做一次，后续复用结果；
- 固定知识写入 `penpot-construction-base.md`，页面卡只提交相对底包的差量；
- 已确认事实不再由子任务复核；只有快照过期或真实写入失败时才刷新相关条目；
- 不让低成本模型读取整份仓库工作方法；调度者只注入底包和本页必要证据；
- 低成本任务保持只读，不打开 Penpot；
- 一个 Manifest 只负责一个路由或紧密关联的状态组；
- 不重复读取整棵 Penpot 图层树；
- 每个画板只允许一次受控写入和一次验收循环；
- 导出或连接失败时不自动重试；
- 不让低成本模型同时承担理解、设计、写入和自验收。

## 12. 失败处理

- 发现错字体、假素材、组件错用、严重重叠或结构方向错误时，直接标记 `REJECTED`，不在坏稿上持续打补丁。
- 废稿必须位于独立页面；删除前核对文件 ID、页面 ID 和页面名，并获得明确授权。
- 失败原因应回写工作方法，但不能把单次偶发问题扩成无关项目的通用规则。
- 每批结束删除或归档本批次产生且未被正式画板引用的临时截图、上传缓存、失败组件源和被拒绝任务；不得误删复用组件、Token、真实素材或历史证据文档。

### 12.1 清批检查

每批结束必须执行一次只读库存并完成清理：

- 页面：删除本批新建且为空的页面；保留已有历史证据页需明确说明；
- 画板：删除失败稿、重复稿、半成品和不在任务清单中的临时画板；
- 图层：清理孤儿顶层图层、施工标签和调试说明；
- 组件：保留被正式画板实例引用的组件源；删除本批新建、无实例引用且不可复用的组件源；
- 缓存：清理插件 `storage` 中的上传分块、媒体对象 ID、临时 shape ID 和批次列表；
- 本地：删除 `/tmp` 中的临时截图和测量文件；被拒绝的调度任务归档。

清理后重新列出页面、顶层画板、组件和缓存键，确认无垃圾中间产物，再结束批次。
